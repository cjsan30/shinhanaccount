# 최신 결정사항

## 2026-11-18 설정 정리: 첫 화면 목록, 백업·복원 분리, 누락 가능성 점검 없앰

- 설정 첫 화면의 메뉴 카드에서 설명 줄을 지우고 제목만 남긴 한 줄 목록(높이 64px, 제목 19px)으로 줄인다. 자동 분류 규칙은 지금처럼 데이터 관리 안에 둔다.
- 데이터 관리 → 백업 · 복원을 "백업 만들기"(안내 · 백업 비밀번호 · [암호화 백업 저장])와 "백업에서 복원"(안내 · [백업 파일 선택] · 고른 파일 이름 · 복원 비밀번호 · [백업으로 복원하기]) 두 상자로 나눈다. 안내 문장은 기존 두 문장을 상자마다 하나씩 나눠 쓴다.
- 데이터 관리의 "누락 가능성 점검"을 없앤다. 실제 누락을 찾지 못하고, 보여 주던 숫자(분류 필요·기간 외 결제·중복 확인 필요)는 다른 화면과 겹치거나(기간 외 결제는 지난 기간 결제까지 세어) 의미가 약했다. 데이터 관리에는 자동 분류 규칙 · 백업 · 복원 · 데이터 초기화만 남는다.
- 그 안에만 있던 [방금 가져온 내역 실행 취소]는 가져오기 직후 열리는 분류 필요 화면의 가져오기 결과 아래로 옮기고 [방금 가져온 내역 되돌리기]로 부른다. 아래에 "앱을 닫기 전까지만 되돌릴 수 있습니다."를 둔다. 되돌리면 가져오기 결과 요약도 함께 지운다.
- 가져오기에서 [이 파일을 사용보고서에도 추가]를 켜서 사용보고서에 붙은 입출금내역 PDF도 되돌리기로 함께 지운다. 그때 알림은 "방금 가져온 결제 내역과 사용보고서에 추가한 입출금내역 PDF를 되돌렸습니다."

## 2026-11-17 고대비 모드 없앰

- 설정 → 접근성 · 개인화에서 [고대비 모드]를 없앤다. 남는 설정은 글자 크기와 진동 피드백이다. 설정 목록 부제는 "글자 크기 · 진동"으로 바꾼다.
- 이유: 기본 화면의 글자 대비가 이미 7.3~14.7:1(WCAG AAA)이라 고대비가 더해 주는 것은 테두리 정도였다. 반면 고대비에서만 생기는 글자색·버튼 색 오류가 계속 나왔다(2026-10 실기기 점검, `!important` 정리). 고대비가 꼭 필요하면 Android 자체 설정(글자 크기, 색상 반전, 고대비 텍스트)을 쓴다.
- 기본 테두리 색은 바꾸지 않는다. 테두리 3:1 시안(카드 전체 밝게 2안, 입력칸만 밝게 1안)을 비교했으나 사용자가 현재 색에서 문제를 찾지 못해 취소했다.
- 이미 고대비를 켜 둔 기기는 업데이트 뒤 기본 화면으로 돌아간다. 저장된 값은 읽을 때 버린다. 다음 출시 노트에 한 줄 적는다.

## 2026-11-17 비밀번호가 걸린 영수증·거래증빙 PDF

- 영수증·거래증빙에 PDF를 첨부하면 바로 열어 본다. 비밀번호가 걸려 있으면 첨부는 하되 "비밀번호가 걸린 PDF가 있습니다. 파일 카드에서 비밀번호를 확인해 주세요."를 보여 준다.
- 그 파일 카드에 "비밀번호가 걸린 PDF입니다" / "비밀번호를 확인해야 보고서에 넣을 수 있어요. 비밀번호는 저장하지 않아 앱을 다시 열면 다시 입력해야 합니다." / [PDF 비밀번호] 칸 · [확인]. 틀리면 "비밀번호가 맞지 않습니다. 다시 입력해 주세요.", 맞으면 "비밀번호를 확인했습니다."
- 확인하지 않은 파일이 있으면 [보고서 생성]을 막고 "비밀번호를 확인하지 않은 PDF N개가 있습니다. 파일 카드에서 비밀번호를 입력하고 [확인]을 눌러 주세요."를 보여 준 뒤 그 카드로 이동한다.
- 비밀번호는 저장하지 않는다(입출금내역과 같은 원칙). "비밀번호 필요" 표시만 저장한다.
- 열 수 없는 PDF(손상 등)는 첨부하지 않고 "이 PDF를 열 수 없습니다. 파일이 손상됐을 수 있어요. 다시 저장해서 추가해 주세요."를 보여 준다.

## 2026-11-16 계획표 OCR 정확도 (작업 D)

- 계획 검토 화면에서 정주비 50만·학습공간비 20만·합계 70만(40만 원형은 그 기준)과 맞지 않으면, 저장을 누르기 전부터 안내 문구(예: "정주비 합계를 500,000원으로 맞춰 주세요.")를 금액 칸 아래에 보여 주고 틀린 칸에 빨간 테두리를 그린다. 합이 안 맞는 묶음은 어느 칸이 틀렸는지 알 수 없으므로 그 묶음의 칸을 모두 표시하고, 항목 최대치를 넘은 칸은 그 칸만 표시한다. 차이 금액은 따로 보여 주지 않는다(사용자 결정). 처음 설치 화면에서 [다음]을 눌렀을 때는 같은 문구를 한 번 더 띄우지 않고 첫 빨간 칸으로 이동한다.
- 스크린샷 읽기는 글자만이 아니라 글자 위치도 받아 표의 "예상금액" 칸에서만 금액을 읽는다. 소계·합계·"최대 N만원" 안내·비율은 금액으로 읽지 않는다. 사이트 표의 행 순서(주거비→식비→교육비→교통비→스터디카페→카페→독서실)로 행을 정하고, 읽힌 항목 이름이 있으면 이름을 따른다. 묶음에서 읽힌 금액만으로 한도가 채워지면 못 읽은 칸은 0으로 본다. 못 읽은 칸을 한도에서 빼서 계산해 채우지는 않는다(다른 칸의 오인식이 숨겨지므로).

- 붙여넣은 계획표 글은 기존 글자 읽기 방식을 그대로 쓴다.

## 2026-11-16 PDF 4.5MB 목표와 앱 안 미리보기 (작업 C)

- PDF 크기 목표 4.5MB는 4,500,000바이트(1MB=1,000,000바이트)로 잡는다. 어떤 파일 앱에서 봐도 4.5MB 이하로 보이게 하기 위해서다. 화면에 보이는 MB 표시도 같은 기준으로 바꾼다.
- 사용보고서 맨 아래 버튼은 [미리보기] 하나다(기존 [PDF 생성]을 대체). 누르면 앱 안에서 PDF를 만들고 페이지를 이미지로 그려 전체 화면에 위에서 아래로 보여 준다. 위에는 "N쪽 · 0.0MB", 페이지를 누르면 크게 보기, 아래에는 [닫기]·[이대로 PDF 생성]을 고정한다.
- [이대로 PDF 생성]은 미리 본 그 파일을 다시 만들지 않고 그대로 Downloads에 저장한다. [닫기]나 Android 뒤로 버튼은 저장하지 않고 미리보기만 닫는다.
- 저장 뒤 "생성 결과" 칸은 유지하고 버튼 이름을 [PDF 열기]로 바꾼다(기기 PDF 앱에서 열기). → 1차 확인 뒤 아래로 바꿈.
- (1차 확인 뒤) 저장 결과는 누른 버튼 아래에 둔다: [미리보기] → 저장 안내 → "만든 보고서". "만든 보고서"는 최근 5개(생성 날짜·시각, 크기, [열기])를 보여 주고 사용보고서를 닫았다 열어도 남는다. 기기에는 파일 위치·이름·크기·저장 시각만 저장한다. 파일 앱에서 지운 보고서는 [열기] 때 "파일을 찾지 못해 목록에서 뺐습니다. 파일 앱에서 지웠을 수 있습니다."로 알리고 목록에서 뺀다. [보고서 초기화]는 이 목록을 지우지 않는다.
- (2차 확인 뒤) 파일 앱에서 지운 보고서는 사용보고서를 열 때와 다른 앱에서 돌아올 때 앱이 확인해 안내 없이 목록에서 바로 뺀다. [열기] 때의 "파일을 찾지 못해…" 안내는 그 사이에 지운 경우를 위해 남긴다.
- (2차 확인 뒤) 저장이 끝나면 버튼 아래 저장 안내 글(위치·크기·영수증 미연결) 대신 "사용보고서가 생성되었습니다." 말풍선만 띄운다. 크기는 "만든 보고서" 목록에, 영수증 미연결은 "영수증 연결 확인"에 이미 나온다. 저장 위치는 따로 표시하지 않는다(사용자 결정).
- (1차 확인 뒤) 줄바꿈: 단어 중간에서 끊지 않고, 두 문장 이상인 짧은 안내는 문장마다 새 줄로 시작한다. 앱 전체 문구를 휴대폰 폭에서 점검해 맞춘다(별도 PR).
- 사용보고서 도움말의 마지막 단계도 새 흐름에 맞춰 바꾼다: "미리보기로 확인하고 PDF를 생성하세요" / "[미리보기]에서 누락과 글자 선명도를 확인한 뒤 [이대로 PDF 생성]을 누르면 저장됩니다."

## 2026-11-05 카드 파일 앞 3자리 일치 안내 문구

- 신한카드 이용내역 파일은 이용카드를 끝 4자리 중 앞 3자리까지만 보여 준다(마지막 자리는 `*`). 앞 3자리가 같은 행을 찾았을 때 미리보기 경고를 "카드번호 3자리가 동일한 결제내역 N건을 찾았습니다. 다른 카드 내역과 섞이지 않았는지 확인해주세요."로 바꾼다(사용자 결정). N은 앞 3자리가 같은 행 수다. 기존 "파일 안에서 4자리를 확인할 수 없습니다"는 대조에 실패한 것처럼 읽혔다.
- [확인 후 계속 진행]을 눌러야 가져오는 동작과 2026-08-05 카드 식별 정책은 그대로다. 파일에 카드 식별값이 없거나 계좌 PDF에서 계좌번호를 찾지 못한 경우는 기존 문구를 유지한다.

## 2026-11-03 'PDF 생성' 화면 이름을 '사용보고서 작성'으로

- 공식 서류 이름(지원금사용보고서)에 맞춰 홈 바로가기, 화면 제목, 앱 안내 단계, 도움말 제목, 앱 정보 고지의 'PDF 생성'을 '사용보고서 작성'으로 바꾼다(사용자 결정). 결과물이 무엇인지 바로 알 수 있게 하려는 것이다.

## 2026-11-03 거래내역 가져오기 미리보기 안내 문구 정리

- 가져오기 미리보기에서 "가져온 출금 내역은 분류 필요 목록에서 ~ 분류할 수 있습니다"(은행)와 "가져오기 전 자동 분류 결과를 적용합니다"(카드)를 뺀다. [내역 가져오기]를 누르면 곧바로 분류 필요 화면으로 넘어가 설명이 겹친다(사용자 결정).
- [이 파일을 제출 PDF에도 추가] 체크박스 아래의 "원본을 보관합니다. 보호된 PDF 비밀번호는 저장하지 않으며, 생성할 때 다시 입력합니다"도 뺀다. 비밀번호가 필요한 첨부는 PDF 생성 화면에 비밀번호 입력 칸이 열려 있어 따로 안내하지 않는다(사용자 결정). 비밀번호를 저장하지 않는 동작은 그대로다.

## 2026-11-01 PDF 생성의 입출금내역도 계좌 끝 4자리 확인

- PDF 생성 화면에서 직접 첨부한 입출금내역 PDF는 바로 읽지 않는다. "계좌 확인이 필요합니다" 아래 [계좌 끝 4자리 / PDF 비밀번호(있는 경우)] 칸과 [표 읽기] 버튼을 보여 주고, 끝 4자리가 파일의 계좌와 맞을 때만 표를 읽는다(사용자 결정: 비밀번호 유무와 상관없이 모든 PDF). 원본 다시 첨부도 같다.
- 끝 4자리가 다르면 "입력한 계좌 끝 4자리와 파일의 계좌 정보가 다릅니다"로 막는다. 파일에서 계좌번호를 찾지 못하면 거래내역 가져오기처럼 안내 후 [그래도 첨부]를 눌러야 첨부한다(사용자 결정).
- 확인 전 PDF는 표를 읽지 못한 PDF와 같이 제출서류 생성을 막는다. 거래내역 가져오기에서 이미 확인을 거쳐 함께 첨부된 PDF와 이미 표를 읽어 둔 기존 첨부는 다시 묻지 않는다.

## 2026-10-25 이미지 압축을 기기 쉬는 시간에 기대지 않게

- PDF·OCR용 JPEG 압축을 `canvas.toBlob`에서 동기 방식(`toDataURL`)으로 바꾼다(사용자 결정). Galaxy S25 Ultra(WebView 155)에서는 화면에 변화가 없으면 브라우저가 쉬는 시간(idle)을 주지 않아 `toBlob`이 호출마다 약 4초를 기다린 뒤에야 압축했다. 영수증 24장 PDF가 약 300초 걸렸고, 회차마다 57~200초로 크게 흔들린 것도 이 대기 때문이었다.
- 압축 품질·해상도·용량 기준은 바뀌지 않는다. 같은 조건에서 영수증 24장 처리 시간이 약 4~5초로 줄었다. 압축하는 동안(장당 약 0.1초) 화면이 잠깐 멈출 수 있지만 장마다 한 번씩 쉬어 취소할 수 있다.
- 이전 성능 측정의 처리 시간(중앙값 116초 → 45초)은 이 대기 시간이 섞인 값이므로 근거로 쓰지 않는다. 결과 PDF 크기(12.6MB → 2.7MB)는 매번 같아 그대로 유효하다.

## 2026-10-25 PDF 작업 중에는 화면 켜짐 유지

- 영수증 파일을 추가해 날짜를 읽는 동안과 PDF를 만드는 동안에는 화면이 자동으로 꺼지지 않게 한다(사용자 요청). 화면이 꺼져 잠기면 앱의 처리가 멈춰, 영수증이 많을 때 기기의 화면 자동 꺼짐 시간(최대 10분)보다 오래 걸리는 작업이 끝나지 않았다.
- 작업이 끝나거나 취소되면 바로 원래 자동 꺼짐 설정을 따른다. 작업 중 다른 앱으로 나갔다가 돌아오면 다시 켜짐을 유지한다. 새 권한은 필요 없다.

## 2026-10-24 "미정 지출" 문구를 "분류 필요"로

- 어느 항목에 넣을지 아직 정하지 않은 결제를 화면에서 "미정 지출" 대신 **"분류 필요"**로 부른다(사용자 결정). "미정"은 무엇이 정해지지 않았는지와 사용자가 할 일이 드러나지 않았다.
- 대시보드 버튼·목록 제목은 "분류 필요 N건", 문장 속에서는 "분류 필요 목록", 되돌리기 버튼은 "분류 필요로 되돌리기", 결제 알림의 버튼은 "나중에 분류"로 쓴다. 비어 있을 때는 "현재 기간에 분류할 결제가 없습니다."
- 코드의 상태 이름(`undecided`)과 동작은 바뀌지 않는다. 이전 문서의 "미정 지출"은 같은 뜻이다.

## 2026-10-23 온보딩은 처음 한 번만, 새 기간 계획은 대시보드에서 확정

- 온보딩(지원자 질문·권한·계획표)은 계획표 기록이 한 번도 없는 처음 사용자에게만 보여 준다(사용자 결정). 지금까지는 기존 사용자도 새 정책 기간에 확정된 계획표가 없으면 온보딩 첫 화면으로 돌아갔다.
- 기존 사용자가 새 기간에 계획표가 없으면 대시보드를 그대로 보여 주고 맨 위에 "이번 기간 계획표를 확정해 주세요" 안내를 띄운다. [지난 계획 그대로 확정]은 가장 최근 계획을 이번 기간 계획으로 바로 확정하고, [수정 후 확정]은 설정 → 데이터 관리의 계획표 항목을 펼쳐 연다(사용자 선택). 지난 계획이 지원 유형 기준에 맞지 않으면 [지난 계획 그대로 확정]은 보이지 않는다.
- 확정 전에 받은 결제는 지금처럼 대기열에 보관하고 확정하면 반영한다.
- 고대비 모드에서 안내 상자 버튼(이 안내와 결제 알림 인식 중단 안내)이 노란 배경에 흰 글자가 되어 보이지 않던 문제를, 다른 밝은 버튼처럼 흰 배경·검은 글자로 고친다.

## 2026-10-23 새 정책 기간이 시작되면 이전 기간 PDF 자료 정리

## 2026-10-10 편의 개선·지원금 일부 금액 결정

- 미정 지출의 `지원금 반영 금액`은 실제 결제 중 지원금으로 처리할 부분이다. 원결제 금액·취소·중복 판단·원본 은행/영수증 이미지는 변경하지 않는다. 예산·경고·위젯·PDF 요약의 사용액만 지원금 반영 금액으로 집계한다.
- 금액은 미정 지출에서 분류 전에 수정한다. 남은 실제 결제 금액 이하의 양의 정수만 허용하며, 0원 처리는 사업 무관 제외로 안내한다. 미정 상태에서는 예산에 반영하지 않는다.
- 부분 취소는 기존 분류를 유지하면서 금액 재확인을 안내한다. 지원금 반영액은 실제 남은 금액을 넘지 않도록 제한한다. 사용자가 미정으로 되돌리면 이전 분류/반영액을 참고해 금액을 다시 정하고 분류한다. 전체 취소는 사용액 0원이다.
- 홈·미정 지출에서 거래내역 가져오기로 진입한다. 사업 무관 제외 확인을 취소하면 선택은 유지한다.
- 영수증은 일괄 저장 후 날짜 OCR 진행 상태를 표시한다. 전체/미연결/날짜 확인 필터, 연결 완료 접기, 다음 미연결 이동을 제공한다. 날짜만 OCR하고 사용자가 결제를 한 번 탭하는 기존 연결 방식은 유지한다.
