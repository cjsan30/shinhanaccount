# 최신 결정사항

## 기준 기기와 배포

- 1차 실제 검증 기기: Samsung Galaxy S25 Ultra / Android 16
- 최소 지원 OS: Android 10(API 29). 직접 파일 저장과 현재 보안 API를 일관되게 제공하기 위한 기준이다.
- APK는 당분간 범용 ABI로 배포한다. 초기 사용자 기기 구성이 확인된 뒤 release만 `arm64-v8a`로 축소한다.
- 초기 배포: 서명 APK를 4명에게 직접 배포
- 각 사용자의 데이터·정책·카드 끝 4자리는 독립적으로 기기 내 암호화 저장

## 결제 알림과 분류

- 사용자는 앱 초기 설정에서 카드 끝 4자리를 입력하고 결제 알림 접근을 허용한다.
- 1차 승인 형식: `[Web발신] [신한체크승인] 사용자(3741) 07/24 17:58 (금액)8,000원 삼성웰스토리(주)크래프톤정`
- 추출값: 카드 끝 4자리, 거래 시각, 금액, 상호명
- 원문 알림은 저장하지 않으며 DB·로그·백업에 포함하지 않는다.
- 삼성웰스토리 8,000원은 정주비/식비, 그 외 삼성웰스토리는 학습공간 지원비/일반카페로 분류한다.
- 취소 알림은 카드·금액·상호명이 모두 일치하는 단일 전체 취소만 자동 반영한다. 복수 후보와 부분 취소는 사용자가 대상과 취소 금액을 확인해 반영한다.

## 2026-08-19 채팅+ 결제 알림 수신 결정

- Galaxy S25 Ultra에서 신한카드의 `확인된 발신번호` 알림은 표준 SMS 저장소가 아닌 삼성 메시지 채팅+ 알림으로 전달될 수 있다.
- 자동 수신 경로는 삼성 메시지(`com.samsung.android.messaging`), 신한 SOL뱅크(`com.shinhan.sbanking`), 신한카드(`com.shinhancard.smartshinhan`), 신한 SOL Pay(`com.shcard.smartpay`) 알림 접근을 사용한다.
- 원본 삼성 메시지 알림은 앱이 임의로 지우지 않는다.
- 같은 앱 안의 거래 식별은 결제 시각·상호명·금액과 알림 게시 시각(밀리초)을 포함한 출처 ID를 사용한다. 앱 간에는 같은 카드·승인 시각·금액·상호명이 90초 안에 도착하면 한 건으로 합친 뒤 그 짝을 소진한다. 이후의 동일 조건 알림은 새 결제로 저장한다.
- 같은 알림의 재게시·묶음 갱신은 출처 ID로 제외한다. 의미가 같은 거래를 자동 삭제하지 않으며, 누락 방지를 중복 자동 제거보다 우선한다.
- 알림 원문은 저장하지 않는다. 출처 ID는 필요한 필드를 해시한 값이며, 진단 이력에는 본문 길이와 처리 단계만 기록한다.

## 정책과 알림

- 정책 기간: 매월 15일 00:00부터 다음 달 10일 23:59:59까지 (한국 시간)
- 기본 기간의 매월 11~14일 결제는 어느 정책 기간에도 포함하지 않으며 예산 집계·경고·현재 기간 결제 목록에서 제외한다. 원본 거래 기록은 삭제하지 않는다.
- 사용 가능 기간은 계획표 검토 화면에서 시작일·종료일을 직접 설정한다. 예산·가져오기·영수증 후보·제출 PDF·네이티브 경고·위젯은 같은 기간을 사용하며, 없는 날짜는 월말로 맞춘다.
- 정책은 기본값으로 자동 생성하지 않는다. 사용자가 정책표를 입력·검토·확정한 뒤에만 예산을 사용한다. 정주비 500,000원·학습공간 지원비 200,000원은 정책 입력 시의 상한이다.
- 카테고리별 알림 기본값: 50%, 80%; 사용자가 슬라이더로 변경 가능
- 두 경고 슬라이더는 각각 1~99%의 고정 범위를 사용하며, 한 값을 옮겨도 다른 슬라이더의 길이·범위는 바뀌지 않는다.
- 수동 분류로 임계치 도달 시에도 자동 분류와 동일하게 로컬 알림을 보낸다.
- 사용률은 앱과 위젯 모두 소수 첫째 자리에서 일반 반올림한다.

## 내역 가져오기와 정책 입력

- 신한카드 앱의 `.csv`·`.xls`·`.xlsx` 이용내역은 카드 끝 4자리 기준으로 가져온다. 신한은행 입출금내역 PDF는 계좌 끝 4자리 기준으로 읽어 정책 기간 안의 출금 행을 미정 지출 후보로 가져온다.
- 첫 가져오기는 개발용 데모 거래를 실제 거래로 교체하고, 이후 동일 파일 거래는 출처·승인 식별값으로 중복을 제외한다. 카드·은행 간 같은 날짜·금액·근접 시각은 상호명이 달라도 병합 후보로 제시하고 사용자가 Yes / No로 확정한다. 확정 결제의 분류는 병합 시 유지한다.
- `승인`·`결제확정`이며 취소 상태가 비어 있는 행만 장부 후보로 처리한다.
- 출시용 빌드는 빈 장부로 시작하며, 개발용 미리보기에서만 데모 데이터를 사용한다.
- 정책표는 모바일 웹의 스크린샷 이미지 OCR로 초안을 만든다. OCR 결과가 비정상적이면 같은 화면에서 표 형식으로 직접 수정·입력한다.
- OCR 결과는 자동 확정하지 않는다. 사용자가 한도·카테고리별 계획 금액을 검토·수정한 뒤 `정책 확정`을 눌러야 적용한다.
- 신청해 웹사이트의 직접 로그인·세션 연동은 하지 않는다. 공식 API나 내보내기 파일이 제공될 때만 별도 연동을 검토한다.
- 정책 확정·예산 표시는 사용처가 아닌 지원 항목 7개(주거비, 식비, 교육비, 교통비, 스터디카페, 카페, 독서실)를 기준으로 한다. 사용처는 개인별 자유 입력 설명으로 취급한다.

## 카드 식별·파일 가져오기 안전 정책 (2026-08-05)

- 앱 첫 화면에서 앱 알림 권한과 결제 알림 접근의 목적·처리 범위를 안내한 뒤 정책 온보딩을 시작한다.
- 카드 끝 4자리는 사용자가 직접 입력한다. 기본 표시는 `••••`이며, 우측 마스킹 해제 버튼으로만 확인한다.
- 카드사 엑셀의 마스킹 카드 식별값에서 설정 카드 끝 4자리의 앞 3자리와 같은 행만 가져온다. 다른 카드 행은 제외한다.
- 동일 앞 3자리의 서로 다른 실제 카드가 파일의 별도 카드 식별자로 식별되면 파일을 거절하고 `카드 하나만 선택해 결제 내역을 다시 받아 주세요.`를 표시한다.
- 마스킹 값만으로 서로 다른 실제 카드를 구분할 수 없으면 카드사 앱에서 카드 하나를 선택해 파일을 받는 것이 사용자 책임임을 미리보기에서 안내한다.
- 가져온 거래에는 사용자가 설정한 카드 끝 4자리를 내부 연결한다. 이는 이후 취소 알림 매칭에 사용하며 화면에는 기본 마스킹한다.

## 2026-08-17 출시 준비 결정

## 2026-08-19 저장·복구 결정

- Android에서는 거래·정책·자동분류 규칙을 SQLCipher 암호화 SQLite 한 곳에 저장한다. 기존 `localStorage` 데이터는 암호화 저장과 재조회가 성공한 뒤에만 삭제한다.
- 카드 끝 4자리와 미처리 승인 대기열은 Android Keystore 기반 암호화 설정 저장소에 둔다. 위젯에는 화면 표시에 필요한 집계 스냅샷만 둔다.
- 백업과 증빙 PDF는 공유 화면을 열지 않고 `Downloads/신청해 계산기`에 직접 저장한다. 파일명에는 생성 시각을 붙인다.
- Android가 직전 실행을 사용자 강제 종료로 판정하면 다음 실행에서 자동 수신 중단 가능성과 엑셀 복구 경로를 안내한다.
- 결제 목록은 거래 시각 최신순으로 표시한다.
- 결제 목록은 상호명·결제시간·금액을 고정 열로 정렬하고, 상단에는 적용 기간 전체 결제 건수만 표시한다.

## 2026-08-19 성능·저장 최적화 결정

- 엑셀·PDF 라이브러리와 온보딩·백업·가져오기·증빙 화면은 실제로 열 때 로드한다. APK 내부 청크를 읽는 방식이므로 네트워크는 필요 없다.
- 승인 알림은 네이티브 수신 이벤트로 대기열에 넣고, 앱 실행·화면 복귀 시 한 번 동기화한다. 고정 주기 폴링은 사용하지 않는다.
- 결제 목록은 앱을 처음 연 시각으로 제한하지 않는다. 앱을 자정 이후에도 계속 사용해 자동 분류된 결제가 총액에는 반영되지만 목록에서 빠지는 일을 막기 위해, 저장된 분류 완료·취소 거래를 모두 표시한다.

## 2026-08-29 Play 인앱 업데이트 결정

- Google Play로 설치한 앱은 실행·화면 복귀 시 Play Core의 업데이트 가능 여부를 확인한다. 직접 설치한 APK와 debug 빌드에서는 안내가 나타나지 않을 수 있다.
- 일반 기능 개선은 유연한 업데이트(Flexible update)로 안내한다. 사용자는 다운로드 중에도 앱을 계속 사용할 수 있고, 완료 후 `다시 시작`을 선택할 때만 새 버전을 적용한다.
- 보안·데이터 손상처럼 앱을 계속 쓰면 위험한 긴급 업데이트가 생길 때만 즉시 업데이트(Immediate update)를 별도로 검토한다.

## 2026-08-20 공개 배포 권한 결정

- Google Play 공개 배포를 목표로 `READ_SMS`와 `RECEIVE_SMS` 권한 및 SMS BroadcastReceiver를 앱에서 완전히 제거한다.
- 자동 결제 인식은 사용자가 명시적으로 허용한 네 개의 지원 앱 알림 접근만 사용한다.
- 앱은 등록 카드와 일치하는 신한카드 승인 알림의 거래 시각·금액·상호명만 암호화 저장하며 원문, 발신자, 다른 알림은 저장·전송·삭제하지 않는다.
- 알림 접근이 꺼졌거나 지원 앱을 사용하지 않는 기기에서는 카드 이용내역 가져오기와 직접 지출 등록을 복구 경로로 제공한다.
- 첫 Play 제출 버전은 `1.2`(`versionCode 3`)로 올리고, 서명 AAB와 내부 테스트 트랙으로 먼저 검증한다.
- 앱 상태는 암호화 SQLite에서 설정·거래·정책·자동분류 규칙 테이블로 나눠 저장하고, 변경된 행만 갱신한다.

## 2026-10-07 예산 조정 결정

- 정주비는 정주비 안에서, 학습공간비는 학습공간비 안에서만 세부 항목의 계획 금액을 이동한다. 대분류 간 이동은 허용하지 않는다.
- 가져올 항목의 이번 기간 미사용 예산(계획에서 분류 완료 순사용액을 차감한 금액)만 이동할 수 있다. 취소는 순사용액에 반영하며 기간 외·미정·제외 거래는 차감하지 않는다.
- 계획이 0원인 항목도 받을 항목으로 선택할 수 있다. 대분류 총액·설정된 항목별 한도·실제 거래의 금액과 분류는 유지한다.
- 대분류 상세 및 설정 → 데이터 관리 → 계획표에서 예산 조정을 제공한다. 이번 기간 계획만 수정하고 다음 기간의 예약 계획은 보존한다.
- PDF에는 최종 계획·실제 사용·잔액만 표시한다. 최초 계획, 증감 열, 조정 이력·설명은 추가하지 않는다.
- Android 암호화 저장소에 저장이 성공한 뒤 화면에 반영한다. 새 데이터 스키마·외부 서비스·권한은 추가하지 않는다.
- 기존 1.3.6 / code 10 AAB는 이 기능을 포함하지 않는다. 추가 수정과 검증이 끝난 소스로 서명 릴리스를 다시 생성한 뒤 업로드해야 한다.
- 증빙 이미지는 원본 비율을 유지한 채 페이지 안에 `contain` 방식으로 배치해 일반 사진도 잘리지 않게 한다. PDF 생성 완료 후 미리보기 URL과 이미지 버퍼 참조를 해제한다.
## 2026-10-07 최신 릴리스 산출물 재생성

예산 조정 및 실기기 검증 완료 소스를 포함한 1.3.6 / code 10 서명 AAB를 다시 생성했다. 최신 업로드 파일은 `audit/release-1.3.6-budget/shinhanhae-1.3.6-10-release.aab`(33,026,908B)이며, 기존 `audit/release-1.3.6/`의 AAB는 예산 기능이 없는 이전 산출물이므로 사용하지 않는다. 웹 307개, Android debug/release 각 27개, 소스 보안·서명·production 구성·bundletool 구조·16KB 정렬 확인 통과. Play 업로드는 사용자에게 인계한다.
