# 최신 결정사항

## 2026-10-27 공식 출처 링크와 기관명 정리 (금융 기능 거부 대응)

- 금융 기능 선언이 같은 사유로 계속 거부된 시점이 2026-10-10에 비공식 고지와 공식 출처 링크 2개를 넣은 때와 겹친다(사용자 판단). 은행·재단 이름과 공식 사이트 링크가 금융 서비스로 읽혔을 가능성을 줄인다.
- 앱: 공식 사이트로 가는 링크 버튼을 모두 없앤다(온보딩, 계획 설정, 데이터 관리, 앱 안내). 고지는 기관 이름 없이 "개인이 개발한 지원금 관리 도구이며, 공식 앱이 아닙니다"로 쓴다. 설정 메뉴 이름은 "앱 안내"로 바꾼다. 2026-10-10 "비공식 앱 고지·정보 출처" 결정의 링크 부분을 대체한다.
- 스토어 설명(절충안, 사용자 선택): 정부 정보 출처 누락 거부(제출 9)가 다시 나오지 않도록 사업 안내 링크 1개(`https://shinchunghae.co.kr/`)만 기관 소개 없이 남긴다. 신한 계열 이름은 모두 빼고, 기능 설명은 "카드 이용내역 CSV·Excel, 은행 입출금내역 PDF"처럼 일반 명칭으로 쓴다.
- 앱 안 거래내역 가져오기 화면의 카드사·은행 이름은 지원하는 파일 형식 안내라 유지한다.

## 2026-10-25 이미지 압축을 기기 쉬는 시간에 기대지 않게

- PDF·OCR용 JPEG 압축을 `canvas.toBlob`에서 동기 방식(`toDataURL`)으로 바꾼다(사용자 결정). Galaxy S25 Ultra(WebView 155)에서는 화면에 변화가 없으면 브라우저가 쉬는 시간(idle)을 주지 않아 `toBlob`이 호출마다 약 4초를 기다린 뒤에야 압축했다. 영수증 24장 PDF가 약 300초 걸렸고, 회차마다 57~200초로 크게 흔들린 것도 이 대기 때문이었다.
- 압축 품질·해상도·용량 기준은 바뀌지 않는다. 같은 조건에서 영수증 24장 처리 시간이 약 4~5초로 줄었다. 압축하는 동안(장당 약 0.1초) 화면이 잠깐 멈출 수 있지만 장마다 한 번씩 쉬어 취소할 수 있다.
- 이전 성능 측정의 처리 시간(중앙값 116초 → 45초)은 이 대기 시간이 섞인 값이므로 근거로 쓰지 않는다. 결과 PDF 크기(12.6MB → 2.7MB)는 매번 같아 그대로 유효하다.

## 2026-10-25 PDF 작업 중에는 화면 켜짐 유지

- 영수증 파일을 추가해 날짜를 읽는 동안과 PDF를 만드는 동안에는 화면이 자동으로 꺼지지 않게 한다(사용자 요청). 화면이 꺼져 잠기면 앱의 처리가 멈춰, 영수증이 많을 때 기기의 화면 자동 꺼짐 시간(최대 10분)보다 오래 걸리는 작업이 끝나지 않았다.
- 작업이 끝나거나 취소되면 바로 원래 자동 꺼짐 설정을 따른다. 작업 중 다른 앱으로 나갔다가 돌아오면 다시 켜짐을 유지한다. 새 권한은 필요 없다.

## 2026-10-24 "미정 지출" 문구를 "분류 필요"로

- 어느 항목에 넣을지 아직 정하지 않은 결제를 화면에서 "미정 지출" 대신 **"분류 필요"**로 부른다(사용자 결정). "미정"은 무엇이 정해지지 않았는지와 사용자가 할 일이 드러나지 않았다.
- 대시보드 버튼·목록 제목은 "분류 필요 N건", 문장 속에서는 "분류 필요 목록", 되돌리기 버튼은 "분류 필요로 되돌리기", 결제 알림의 버튼은 "나중에 분류"로 쓴다. 비어 있을 때는 "현재 기간에 분류할 결제가 없습니다."
- 코드의 상태 이름(`undecided`)과 동작은 바뀌지 않는다. 이전 문서의 "미정 지출"은 같은 뜻이다.

## 2026-10-23 온보딩은 처음 한 번만, 새 기간 계획은 대시보드에서 확정

- 온보딩(지원자 질문·권한·계획표)은 계획표 기록이 한 번도 없는 처음 사용자에게만 보여 준다(사용자 결정). 지금까지는 기존 사용자도 새 정책 기간에 확정된 계획표가 없으면 온보딩 첫 화면으로 돌아갔다.
- 기존 사용자가 새 기간에 계획표가 없으면 대시보드를 그대로 보여 주고 맨 위에 "이번 기간 계획표를 확정해 주세요" 안내를 띄운다. [지난 계획 그대로 확정]은 가장 최근 계획을 이번 기간 계획으로 바로 확정하고, [수정 후 확정]은 설정 → 데이터 관리의 계획표 항목을 펼쳐 연다(사용자 선택). 지난 계획이 지원 유형 기준에 맞지 않으면 [지난 계획 그대로 확정]은 보이지 않는다.
- 확정 전에 받은 결제는 지금처럼 대기열에 보관하고 확정하면 반영한다.
- 고대비 모드에서 안내 상자 버튼(이 안내와 결제 알림 인식 중단 안내)이 노란 배경에 흰 글자가 되어 보이지 않던 문제를, 다른 밝은 버튼처럼 흰 배경·검은 글자로 고친다.

## 2026-10-22 앱이 꺼져 있을 때의 즉시 예산 경고에 사용자 규칙 적용(작업 7)

- 앱이 꺼져 있을 때 결제 알림을 받으면, 웹 앱이 마지막으로 보내 둔 사용자 규칙 스냅샷으로 분류해 즉시 예산 경고를 판단한다. 작업 6 이후 생겼던 "앱이 꺼져 있으면 경고가 울리지 않는" 공백이 없어진다.
- 우선순위(정확 일치 → 긴 키워드 → 최근 규칙)와 예산 항목 매핑은 TypeScript가 정해서 보내고, Kotlin은 위에서부터 처음 맞는 규칙만 고른다. 규칙의 지원 구분과 세부항목이 어느 예산 항목에도 맞지 않으면 경고를 보내지 않는다. 최종 분류와 집계는 지금처럼 앱을 열 때 TypeScript가 한다.
- 기간, 상호명 정규화·매칭, 경고 기준 경계는 `app/src/domain/nativeBudgetVectors.json`의 공유 사례로 웹과 Android 테스트가 함께 검증한다.
- 규칙 스냅샷은 앱을 열어 예산 상태를 동기화할 때 갱신된다. 업데이트 직후 앱을 한 번 열기 전에는 스냅샷이 없어 경고가 울리지 않는다.

## 2026-10-22 개인용 기본 분류 규칙 삭제

- 코드에 들어 있던 개인용 기본 분류 규칙(삼성웰스토리 금액별, 서브웨이·맘스터치·맥도날드, 놀유니버스, SR, 아이햅슨)을 웹(`classifyPayment`)과 Kotlin(`classifyForBudget`)에서 모두 삭제한다. 다른 사용자에게는 잘못된 자동 분류가 되기 때문이다.
- 이 규칙들을 기존 사용자의 사용자 규칙으로 옮겨 주지 않는다(사용자 결정). 업데이트 후 이 상호들은 미정으로 들어오고, 필요하면 사용자가 앱에서 직접 규칙을 등록한다. 이미 저장된 내역은 바뀌지 않는다.
- 아이햅슨은 문서에 "미정 처리 후 사용자 제외"로 적혀 있었지만 코드는 즉시 제외했다. 이제 다른 상호와 같이 미정으로 들어온다.
- 작업 7(사용자 규칙을 네이티브로 동기화) 전까지는 앱이 꺼져 있을 때 오는 즉시 예산 경고가 울리지 않는다. 승인은 대기열에 남았다가 앱을 열면 사용자 규칙으로 분류되고 경고 기준을 넘으면 그때 알린다.

## 2026-10-22 카드 내역 가져오기에도 사용자 분류 규칙 적용

- 신한카드 이용내역(`.csv`·`.xls`·`.xlsx`·PDF)을 가져올 때도 결제 알림·직접 등록과 같은 사용자 자동 분류 규칙을 적용한다. 규칙에 맞지 않는 상호는 지금처럼 미정으로 들어온다.
- 지금까지 카드 가져오기는 사용자 규칙을 쓰지 않고 코드에 들어 있던 개인용 기본 규칙만 썼다. 작업 6에서 기본 규칙을 지우면 가져온 카드 결제가 모두 미정이 되므로, 그 전에 사용자 규칙을 적용한다.
- 신한은행 입출금내역의 출금 행은 이전 결정대로 미정 지출 후보로 가져온다. 같은 결제가 카드 내역과 겹쳐 병합 후보가 되므로 사용자가 판단한다.
- 이미 저장된 내역과 병합 시 확정 결제의 분류를 유지하는 규칙은 바뀌지 않는다.

## 2026-10-21 항목별 사용액은 버킷과 카테고리가 모두 맞을 때만 집계

- 홈 위젯의 세부항목 사용액·건수와 빠른 분류 버튼의 순서(건수 기준)도 대시보드·PDF 보고서·예산 경고와 같은 기준을 쓴다. 결제의 버킷과 카테고리가 모두 항목과 일치할 때만 그 항목의 사용으로 센다.

- 첫 가져오기는 개발용 데모 거래를 실제 거래로 교체하고, 이후 동일 파일 거래는 출처·승인 식별값으로 중복을 제외한다. 카드·은행 간 같은 날짜·금액·근접 시각은 상호명이 달라도 병합 후보로 제시하고 사용자가 Yes / No로 확정한다. 확정 결제의 분류는 병합 시 유지한다.
- `승인`·`결제확정`이며 취소 상태가 비어 있는 행만 장부 후보로 처리한다.
- 출시용 빌드는 빈 장부로 시작하며, 개발용 미리보기에서만 데모 데이터를 사용한다.
- 정책표는 모바일 웹의 스크린샷 이미지 OCR로 초안을 만든다. OCR 결과가 비정상적이면 같은 화면에서 표 형식으로 직접 수정·입력한다.
- OCR 결과는 자동 확정하지 않는다. 사용자가 한도·카테고리별 계획 금액을 검토·수정한 뒤 `정책 확정`을 눌러야 적용한다.
- 신청해 웹사이트의 직접 로그인·세션 연동은 하지 않는다. 공식 API나 내보내기 파일이 제공될 때만 별도 연동을 검토한다.
- 정책 확정·예산 표시는 사용처가 아닌 지원 항목 7개(주거비, 식비, 교육비, 교통비, 스터디카페, 카페, 독서실)를 기준으로 한다. 사용처는 개인별 자유 입력 설명으로 취급한다.
