# 실기기 확인 체크리스트

기준: 2026-10-07 내부 디버그 1.3.5 / versionCode 9, Galaxy S25 Ultra / Android 16. 아래 사람의 실기기·파일 확인은 구현 완성도에 포함하지 않는다. 자동 테스트 통과는 실제 알림 수신, 이미지 인식 정확도 또는 출력물 가독성을 보증하지 않는다.

체크 상태는 사용자가 회신한 O 항목과 이번에 에이전트가 검증한 C 항목을 합친 것이다. 사용자 확인을 에이전트의 독립 검증으로 바꾸어 기록하지 않는다. 이번 C 검증 결과와 시험 조건은 아래 별도 표에 정리했다.

## 이번 수정 후 확인

- [x] 고대비 모드에서 계획표·파일 읽기·PDF 생성 등 흰 버튼 글자가 검정으로 읽힌다.
- [x] 작은 화면과 OS 최대 글자 크기에서 제목·빠른 확인·분류 버튼·PDF 창·도움말이 잘리지 않고 모든 버튼에 접근할 수 있다.
- [x] 측정 시작은 0%로 표시되고, 영수증은 ‘장’, 측정 반복은 ‘회’로 구분된다.
- [x] 과거/현재 측정 중 ‘생성 취소’를 누르면 멈추고, 첨부 파일은 남으며 미완료 측정 결과와 파일은 생성되지 않는다.
- [x] 같은 영수증·순서로만 과거/현재 결과가 비교된다. 파일 추가·삭제·순서 변경 시 이전 결과가 사라지고, 더 느림·같음도 사실대로 표시된다.
- [x] 설정 → 데이터 관리 → 계획표 → ‘저장된 계획·기간 수정’에서 기본 15일~익월 10일과 사용자 기간을 확인한다. 변경·확정·완전 종료·재실행 후 기간과 금액이 유지되고 가져오기·예산·영수증 후보·제출 PDF가 같은 기간을 사용한다.
- [x] 날짜를 직접 선택하면 OCR 성공이라고 안내하지 않고 해당 날짜의 결제만 나온다. 결제를 한 번 탭하면 연결되고, 이미 연결된 결제는 다른 후보에서 제외된다.
- [x] 영수증 연결이 없어도 경고 후 PDF 생성이 가능하다. ‘증빙 준비’ 자동 확인도 미연결만으로 실패하지 않는다. 읽지 못한 입출금 PDF는 준비 완료로 처리하지 않는다.
- [x] PDF 도움말의 ‘결제 연결’ 단계가 실제 결제 후보 또는 날짜 입력 위치를 가리킨다. 다음·이전·닫기가 자연스럽다.
- [x] 미정 지출 카드 사이 간격이 일정하다. 카드 CSV·Excel / 은행 PDF 안내와 선택 파일 형식이 일치한다.
- [x] 검증 결과 내보내기에 실제 버전·빌드·플랫폼이 표시된다.
- [x] 카드·알림 접근을 설정하지 않은 초기 상태에서 앱을 완전 종료해도 복구 경고가 뜨지 않는다. 초기 설정을 건너뛴 안내와 계획표 항목 설명이 이해하기 쉽다.

## PDF 품질과 성능 — 목적을 분리해 확인

- [x] 짧은·일반·긴 영수증 최소 3장으로 ‘압축 품질 비교 생성’을 실행한다. default / compact / minimum 3개 파일이 열리고 각각 정확한 바이트 용량이 표시되며 5MB 이하인지 확인한다.
- [x] compact와 minimum의 **모든 페이지**를 확대한다. 원본과 비교해 날짜·금액·상호명·영수증 글자가 읽히고 잘림·다른 행을 침범하는 마스킹이 없는지 확인한다. 이는 시간 비교가 아닌 **가독성·배치 검수**다.
- [x] 영수증 20장 이상을 같은 순서로 넣고 과거 방식 1회, 현재 방식 3회 측정한다. 현재 방식은 중앙값이다. 동일 입력·기기에서 시간과 파일 크기를 함께 비교한다.
- [x] 일반 PDF 생성 후 요약·원본 입출금 이미지·회색 제외 영역·미연결 영수증 별도 묶음·긴 영수증 한 장당 한 페이지를 확인한다. ‘미리보기’로 외부 PDF 앱에서 열린다.

## 초기화와 실제 카드 Excel — 무엇을 검증하는가

- [x] 초기화 3개 범위(결제/미정 지출, 분류 규칙, 정책)의 **선택 가능한 7가지 조합**을 검증용 데이터로 실행한다. 선택한 데이터만 지워지고 선택하지 않은 데이터와 원본 증빙 파일은 유지되는지 확인한다. 결제 초기화 시 연결은 해제된다. 실행 전 취소한 경우에는 아무것도 지워지지 않아야 한다.
- [x] 실제 카드 Excel을 이미 미정 지출이 있는 상태, 이미 분류된 결제가 있는 상태에 각각 가져온다. 같은 날짜·금액·근접 시각이지만 상호명이 다른 카드/은행 거래에 Yes / No가 표시되는지, Yes는 중복 없이 병합하고 기존 분류를 보존하는지, No는 별도 거래를 유지하는지 확인한다.
- [x] 같은 파일 재가져오기에서 중복이 늘지 않고, 은행에만 있는 거래는 누락되지 않는다. 복수 병합 후보가 있을 때 앱이 임의로 확정하지 않는다.

## 사용자가 별도로 진행할 검증

- [x] 실제 승인·전체 취소·부분 취소 알림, 알림 접근 권한 취소 후 재허용. (사용자 확인)
- [x] 홈 위젯 표시와 재부팅 후 유지. (사용자 확인)
- [x] Play 배포 업데이트 이후 기존 데이터 유지. (사용자 확인)

MGC 원본 날짜 손상/OCR 오독의 추가 원인 검증은 취소했다. 테스트를 위해 앱 삭제가 필요하면 검증용 설치에서만 진행한다. 이번 디버그 업데이트는 versionCode를 증가시키지 않는다.

### 검증 중 발견한 안내 개선점

- 미정 지출 상단의 가져오기 요약은 가져온 직후의 집계다. Yes/No를 모두 처리해도 ‘중복 확인 필요 4건’이 남아 실제 남은 확인 건수처럼 보일 수 있었다. **1.3.6 / code 10에서 수정:** ‘가져오기 당시 집계 · 중복 후보’와 ‘현재 중복 확인 필요’를 분리했다. 현재 건수는 실제 미정 거래를 기준으로 Yes/No 직후 갱신하며, 복수 후보도 거래 한 건으로 집계한다. 단위·컴포넌트 및 앱 통합 회귀로 확인했다. 해당 안내 변경의 실기기 시각 검수는 이번 릴리스 생성 작업에서 추가로 실행하지 않았다.
- KFC 원본 사진의 하단 잘림은 앱 출력 과정의 손실이 아니다. 잘린 사진을 추가한 뒤 PDF에서 복원할 수는 없으므로 원본 전체가 들어오도록 재촬영하는 것이 필요하다.

이번 실행은 검증이며 앱 기능·versionCode·APK를 변경하지 않았다. 관련 단위 회귀 3개 파일 16개 테스트도 다시 통과했다. 기존 구현 완성도 95%와 이번 실기기 판정은 별도로 유지한다.

### 데이터 보존과 증거

- 원본 암호화 DB 사본으로 복원했고, 결제·정책·분류 규칙·보고서 첨부·연결 상태 및 증빙 파일의 해시가 검증 전과 같다. 사용자 백업은 수정하지 않았다.
- 시험 영수증만 제거했다. 원본 증빙은 삭제하지 않았으며 생성한 품질 PDF 3개는 휴대폰 Downloads에 남겨 두었다.
- 승인받은 생성 PDF·렌더링·집계 증거는 로컬 `audit/current-device-audit/`에 보관한다. 금융 PDF·이미지·DB 사본은 Git에 포함하지 않는다. 거래 원문 JSON과 원본 영수증 화면은 PC로 내보내지 않았다.
- KFC 원본 확대 미리보기 화면의 추가 저장·대조는 사용자 요청으로 생략했다. 해당 판단은 이미 수집한 기기 내부 압축 해시와 승인된 생성 PDF에 한정한다.

## 예산 조정 - 2026-10-07 실기기 확인 완료

아래 항목은 자동 테스트·에뮬레이터 검증과 별도로 Galaxy S25 Ultra(SM-S938N)의 최신 디버그 1.3.6 / code 10에서 합성 데이터로 실행했다. 삭제 없이 업데이트하고 검증 후 원본 데이터를 복원했다.

- [x] 정주비 상세 → 예산 조정: 교통비의 미사용 예산 50,000원을 계획이 0원인 주거비로 이동한다. 주거비 계획은 50,000원, 교통비 계획은 기존 금액에서 50,000원 차감되어야 한다.
- [x] 학습공간비 상세에서 카페 → 독서실 이동을 확인한다. 정주비 항목은 후보에 없어야 하고, 정주비 조정에도 학습공간비 항목이 없어야 한다.
- [x] 미사용 금액 초과·0원·음수·소수·항목별 한도 초과 시 적용되지 않는다. 받는 항목의 현재 지출이 있어도 실제 결제 금액과 분류는 바뀌지 않는다.
