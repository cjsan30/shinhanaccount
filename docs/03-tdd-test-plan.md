# 지원금 관리 모바일 앱 — 구현 백로그 및 검증 계획

## 1. 구현 순서

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| 0. 프로젝트 기반 | React/Vite/Capacitor/Android 프로젝트, 코드 품질 도구 | 빈 앱이 Android 에뮬레이터에서 실행 |
| 1. 데이터·정책 | SQLite 스키마, 정책 버전, 예산 계산 | 10일 기준 기간과 사용자가 확정한 정책 한도 계산 테스트 통과 |
| 2. 홈·상세 UI | 확정 홈, 두 예산 상세, 내역·미정 결제함 | 시안 흐름과 반응형 화면 검수 통과 |
| 3. 수동 처리 | 수동 결제, 분류, 미정, 제외, 규칙 저장 | 사용자가 모든 결제를 수정 가능 |
| 4. SMS 네이티브 | 권한·승인 파서·중복 방지 | 승인 샘플의 자동 반영 테스트 통과. 취소는 샘플 확보 후 별도 구현 |
| 5. 알림·위젯 | 임계치 알림, 초과 경고, 홈 위젯 | 거래 후 앱·위젯 수치가 일치 |
| 6. 백업·릴리스 | 암호화 내보내기/가져오기, 서명 APK | 4명 테스트 설치·복원 검증 통과 |

## 2. 사용자 스토리

### P0 — 첫 배포에 필수

- 사용자는 처음 실행 시 자신의 카드 끝 4자리와 초기 정책을 설정할 수 있다.
- 사용자는 총 잔액과 두 지원구분 잔액을 홈에서 확인할 수 있다.
- 사용자는 결제를 수동 등록하고 분류·제외·미정 처리를 할 수 있다.
- 사용자는 자동 분류 결제를 미정으로 되돌릴 수 있다.
- 사용자는 정책별 카테고리 계획금액과 사용·잔액을 확인할 수 있다.
- 사용자는 두 알림 기준을 슬라이더로 변경할 수 있다.
- SMS 권한을 허용한 사용자는 승인 문자를 자동 반영받는다.
- 사용자는 초과 직후 취소를 유도하는 알림을 받는다.
- 사용자는 홈 위젯에서 핵심 잔액과 미정 건수를 볼 수 있다.
- 사용자는 실제 취소를 확인한 결제를 직접 취소 확정할 수 있다.

### P1 — 첫 안정화에 포함

- 사용자는 동일 상호명 결제의 분류 규칙을 재사용할 수 있다.
- 사용자는 암호화된 파일로 데이터를 내보내고 복원할 수 있다.
- 사용자는 과거 정책과 현재 정책을 구분해 조회할 수 있다.

### 후속 보류

- Notion 연동, 영수증 OCR·자동 판정, 다중 기기 동기화, iOS 지원, 스토어 공개 배포, 대량 증빙 PDF의 백그라운드 처리

## 3. 기능 검증 체크리스트

### 정책과 집계

- [ ] 7월 10일 00:00 결제는 7월 정책에 반영된다.
- [ ] 8월 9일 23:59 결제는 같은 정책에 반영된다.
- [ ] 8월 10일 00:00 결제는 새 정책에 반영된다.
- [ ] 확정 정책의 정주비·학습공간비·총 한도를 각각 계산하며, 정책 미확정 상태에 숨은 기본 한도를 만들지 않는다.
- [ ] 미정과 제외는 총 사용액·지원구분·카테고리 사용액에 모두 포함하지 않는다.
- [ ] 과거 정책을 수정해도 기존 거래의 배정값이 변경되지 않는다.

### SMS·취소

- [ ] 허용 카드 끝 4자리와 다른 문자는 무시한다.
- [ ] 같은 승인 문자가 두 번 오면 거래가 한 번만 생성된다.
- [x] 결제시각·금액·상호명이 같아도 알림 게시 밀리초가 다른 두 알림은 거래 2건으로 저장된다.
- [ ] 삼성 메시지 묶음 알림이 `[A]`에서 `[A, B]`로 갱신되면 B만 새로 저장된다.
- [ ] 신한 슈퍼SOL과 다른 앱의 알림은 처리하지 않는다.
- [ ] 알림 접근으로 처리한 뒤에도 원본 삼성 메시지 알림은 상단바에 유지된다.
- [ ] 사용자가 취소를 직접 확정하면 알림 없이 사용액을 되돌린다.
- [ ] 취소 SMS 샘플 확보 후 승인번호 우선·복수 후보 거절·부분취소·매칭 실패 경로를 별도 추가한다.

### 분류·알림

- [ ] 규칙 없는 승인 건은 미정으로 생성된다.
- [ ] 상호명+금액 규칙이 상호명 전체 규칙보다 우선한다.
- [ ] 자동 분류 거래를 사용자가 미정으로 바꿀 수 있다.
- [ ] 50%, 80% 알림은 한 정책·카테고리에서 각각 한 번만 전송된다.
- [ ] 슬라이더 값은 1~99%, 서로 다른 오름차순 값으로만 저장된다.
- [ ] 한 슬라이더를 옮겨도 다른 슬라이더의 범위와 길이는 바뀌지 않는다.
- [ ] 앱과 위젯의 사용률이 동일한 일반 반올림 결과를 표시한다.
- [ ] 한도를 넘는 승인 즉시 초과 알림을 보낸다.

### UI·위젯·복원

- [ ] 홈은 확정 시안의 정보 우선순위를 유지한다.
- [ ] 작은 Android 화면에서도 가로 스크롤 없이 핵심 금액이 읽힌다.
- [ ] 위젯과 앱의 잔액·미정 건수가 일치한다.
- [ ] 금액 숨김 위젯은 금액을 표시하지 않는다.
- [ ] 내보낸 암호화 파일을 새 설치 환경에서 정상 복원한다.
- [ ] 저장·암호화·복원 실패 시 기존 데이터가 지워지지 않고 재시도 안내가 표시된다.
- [ ] Android 시스템 뒤로가기는 상세→상위 설정→대시보드 순서로 이동하며 가져오기 필수 화면은 우회하지 않는다.
- [ ] 강제 종료 뒤 실행 시 자동 수신 누락 안내와 거래내역 가져오기 경로가 표시된다.

## 5.1 회귀 방어 기준

- `npm run test:coverage`는 전체 Statements 50%, Branches 45%, Functions 50%, Lines 60% 아래로 내려가면 실패한다. 이는 현재 기준선을 고정하는 최소선이며 최종 목표치가 아니다.
- 도메인 규칙은 정상 경로뿐 아니라 중복·경계값·저장 실패·복원 실패·정책 미확정·역방향 화면 이동을 함께 검증한다.
- Android 단위 테스트는 실제 승인 SMS 파싱과 앱·위젯 반올림 일치를 고정한다.
- MediaStore 직접 저장, Keystore 무효화, 강제 종료 감지, 시스템 뒤로가기는 Android API 의존성이 있으므로 에뮬레이터 및 최종 실기기 체크리스트를 병행한다.
- 기존 단일 SQLite 스냅샷을 정규화 테이블로 옮기는 과정은 round-trip과 변경 행 판별 테스트로 데이터 보존을 고정한다.
- 일반 사진과 긴 영수증은 원본 비율을 유지하고 페이지 영역을 벗어나지 않는지 좌표 계산 테스트로 확인한다.
- SMS 대기열은 수신 이벤트와 앱 시작·복귀 경로를 검증하며 고정 주기 폴링을 전제로 하지 않는다.

## 6. 구현 착수 전 남은 외부 입력

- 카드사 승인·취소 SMS 마스킹 샘플 각 1건
- 사용자별 카드 끝 4자리
- 테스트할 Android 기기/OS 버전
- 수동 분류로 임계치 도달 시 푸시 알림을 보낼지 여부 (현재: 인라인 경고)

### 카드 식별·파일 가져오기

- [ ] 설정 카드 `1111`에서 `111*`, `222*`, `112*`가 섞인 파일은 `111*` 행만 가져온다.
- [ ] 설정 카드 앞 3자리와 같은 서로 다른 `cardIdentity`가 둘 이상이면 가져오기를 거절하고 정해진 문구를 표시한다.
- [ ] 마스킹 식별값만 있는 경우에는 비차단 안내를 표시하고 일치 행을 가져온다.
- [ ] 가져온 거래에 설정한 카드 끝 4자리가 연결되어 취소 SMS 매칭에 활용된다.
- [ ] 첫 실행에서 SMS·알림 권한을 요청한 뒤에만 정책 온보딩을 진행한다.
