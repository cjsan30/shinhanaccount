# 지원금 관리 모바일 앱 — 합의 기준 및 PRD

## 1. 문서 목적과 고정 기준

이 문서는 구현에 앞서 합의된 제품 기준을 고정한다. 별도 변경 기록 없이 기능 범위·정책·화면 구조를 바꾸지 않는다.

| 항목 | 결정 |
|---|---|
| 1차 플랫폼 | Android |
| 앱 형태 | React/Vite 화면을 Capacitor 네이티브 컨테이너로 제공하는 하이브리드 앱 |
| 배포 | 초기 서명 APK 검증 후 Google Play 공개 배포 준비 |
| 사용자 구조 | 각 사용자 데이터·정책·카드 끝 4자리가 완전히 독립적 |
| 데이터 저장 | 기기 내부 암호화 저장. 서버·Notion 동기화 없음 |
| 입력 방식 | 삼성 메시지 카드 승인 알림 자동 처리 + 카드 엑셀·수동 지출 입력/수정·취소 확정 |
| 홈 화면 | 확정된 어두운 톤의 `지원금 관리` 대시보드 구조 |
| 위젯 | Android 홈 화면 위젯 제공 |

## 2. 문제와 목표

지원금 사용자는 휴대폰에서 카드 결제를 하고도, 남은 예산과 분류 미정 건을 따로 정리해야 한다. 앱은 삼성 메시지의 승인 알림을 기기 안에서 처리해 예산 사용량을 갱신하고, 분류가 필요한 결제와 한도 위험만 간결하게 보여준다.

### 성공 기준

- 승인 알림 1건을 수신하면 중복 없이 결제 내역과 예산이 갱신된다.
- 규칙이 없는 결제는 추측하지 않고 `미정`으로 보관된다.
- 카테고리 사용률이 설정한 50%·80% 또는 초과 상태에 도달하면 즉시 알림을 보낸다.
- 사용자가 3번 이내의 탭으로 미정 건을 분류·수정·취소 처리할 수 있다.
- 한 사용자 앱의 데이터가 다른 사용자의 데이터나 서버에 전송되지 않는다.

### 비목표 (v1 제외)

- Notion 양방향 동기화
- 사용자 간 예산 공유·관리자 대시보드
- 영수증 OCR, 결의서 자동 제출
- iOS SMS 자동 수집
- iOS 공개 배포

## 3. 지원금 정책

### 3.1 정책 기간과 한도

| 구분 | 정책 입력 상한 | 기간 |
|---|---:|---|
| 정주비 | 500,000원 | 매월 14일 00:00 ~ 다음 달 10일 23:59:59 (한국 시간) |
| 학습공간 지원비 | 200,000원 | 동일 |
| 총 한도 | 700,000원 | 동일 |

정책은 기본값으로 자동 생성하지 않는다. 위 금액은 정책 입력 상한이며 아래 값은 신청 계획서 예시일 뿐이다. 사용자는 실제 계획서를 입력·검토·확정한 뒤에만 대시보드와 결제 알림 자동 기록을 사용할 수 있다. 값 0원인 카테고리는 사용 기록은 가능하되, 계획금액 대비 알림을 발송하지 않는다. 매월 11~13일은 정책 적용 공백이며 이 기간 거래는 보존하되 예산·경고·현재 기간 결제 목록에 포함하지 않는다.

| 지원구분 | 카테고리 | 계획서 예시금액 |
|---|---|---:|
| 정주비 | 주거비 | 50,000원 |
| 정주비 | 식비 | 200,000원 |
| 정주비 | 교육비 | 0원 |
| 정주비 | 교통비 | 250,000원 |
| 학습공간 지원비 | 일반카페 | 200,000원 |

### 3.2 정책 버전

- 정책은 기간별 버전으로 보존한다. 이미 기록된 과거 결제의 기준을 덮어쓰지 않는다.
- 일반 변경은 다음 매월 14일에 적용한다.
- 같은 기간 중 예외 변경이 필요하면, 사용자가 적용 시작 시각을 명시한 새 정책 버전을 만든다.
- 한도·카테고리 계획·알림 기준을 모두 소진하거나 정책 기간이 끝나면, 다음 기간의 정책을 확정하도록 안내한다.

### 3.3 알림

- 카테고리별 알림 기준은 기본 50%, 80%이며, 사용자는 두 개의 슬라이더로 변경한다.
- 두 값은 1~99%, 오름차순, 서로 다른 값으로 저장한다.
- 두 슬라이더의 시각적 범위는 각각 1~99%로 고정하며, 한 값을 변경해도 다른 슬라이더의 길이는 바뀌지 않는다.
- 승인 알림으로 기준을 처음 넘거나 한도를 초과하면 즉시 로컬 알림을 보낸다.
- 현재 버전은 사용자가 결제 내역에서 취소를 직접 확정하면 알림 없이 사용액만 되돌린다. 취소 알림 자동 매칭은 실제 샘플 확보 후 구현한다.
- 수동 분류·수정으로 기준을 넘긴 경우에도 동일하게 로컬 알림을 보낸다.

## 4. 결제 처리 규칙

### 4.1 승인 알림 수집과 개인정보

- 최초 실행에서 앱 알림 권한과 승인 알림 접근의 목적·저장 범위를 명확히 고지하고 동의를 받는다.
- 삼성 메시지와 신한 SOL의 승인 알림 중 등록 카드 끝 4자리와 일치하는 신한체크승인만 처리한다. 앱은 SMS 읽기·수신 권한을 요청하지 않는다.
- 원문 알림은 저장·전송·삭제하지 않는다. 저장 항목은 거래 시각, 알림 게시 시각, 금액, 정규화된 상호명, 카드 끝 4자리, 상태, 분류 및 생성 출처다.
- 알림 접근이 허용된 동안 게시된 알림만 자동 처리한다. 누락 내역은 신한카드 엑셀 가져오기 또는 직접 등록으로 보완한다.

### 4.2 중복·취소

- 승인번호가 있으면 카드 끝 4자리 + 승인번호로 중복을 제거한다.
- 승인번호가 없고 네이티브 알림 출처 ID가 있으면 거래시각 + 금액 + 상호명 정규화값 + 알림 게시 시각(밀리초)의 해시로 같은 앱의 수신 이벤트만 제거한다. 서로 다른 허용 앱에서 동일 카드·거래시각·금액·상호명이 90초 안에 수신되면 한 승인으로 합치고, 짝지어진 두 알림은 이후 중복 판단에 다시 쓰지 않는다.
- 동일 분·동일 금액·동일 상호의 별도 알림은 각각 보존한다. 출처 ID가 없는 기존·가져오기 데이터에 한해서만 기존 대체키를 호환 목적으로 사용한다.
- 사용자는 실제 취소를 확인한 결제를 직접 취소 확정할 수 있다.
- 취소 알림 자동 매칭·부분취소·`취소 확인 필요` 목록은 실제 취소 알림 샘플 확보 후 구현·검증한다.

### 4.3 분류

- 자동 분류는 저장된 규칙만 사용한다. 규칙이 없거나 모호하면 `미정`으로 저장한다.
- 사용자는 자동 분류된 결제도 언제든 `미정`으로 변경할 수 있다.
- `미정` 결제는 총 사용액·정주비·학습공간비·카테고리 사용액 모두에서 제외한다.
- 미정 결제를 분류하면 해당 정책 버전의 예산에 즉시 반영한다.
- 규칙 저장 범위는 `이번 1회`, `상호명+금액`, `상호명 전체` 중 사용자가 고른다.
- 우선순위는 상호명+금액 규칙이 상호명 전체 규칙보다 높다.

## 5. 화면과 흐름

### 5.1 홈

확정 시안의 구조를 그대로 따른다.

- 제목 `지원금 관리`, 우측 설정 버튼
- 총 잔액, 총 한도·사용액·사용률, 얇은 진행 막대
- `정주비`, `학습공간 지원비` 두 요약 행: 잔액, 사용률, 상세 진입
- 빠른 확인: `미정 지출 N건`, `결제 내역 확인`, `PDF 생성`
- 총 잔액 영역의 보조 버튼: `새 지출` 직접 등록

### 5.2 화면 연결

| 시작점 | 이동 화면 | 주요 행동 |
|---|---|---|
| 정주비 행 | 정주비 상세 | 주거·식비·교육·교통 계획/사용/잔액 확인 |
| 학습공간 지원비 행 | 학습공간 상세 | 일반카페 등 카테고리별 사용 확인 |
| 미정 지출 | 미정 결제함 | 분류, 제외, 규칙 저장, 수동 미정 전환 |
| 결제 내역 확인 | 결제 내역 | 최신순 조회, 수정·분류 변경·삭제·취소 확정 |
| 새 지출 | 직접 지출 등록 | 사용자가 금액·상호명·분류를 직접 입력 |
| 설정 | 정책·카드·알림·백업 | 정책 버전, 카드 끝 4자리, 슬라이더, 데이터 관리 |

### 5.3 위젯

- 기본 표시: 총 잔액, 정주비 잔액, 학습공간 지원비 잔액, 미정 건수
- 탭하면 홈 또는 미정 결제함으로 이동한다.
- 금액을 숨기는 옵션을 제공한다.

## 6. 운영 원칙

- 결제를 카드에서 차단할 수는 없으므로, 초과 직후 즉시 경고해 취소를 유도한다.
- 분류·정책·규칙의 변경 기록을 남겨 사용액 변동의 원인을 추적한다.
- 데이터 내보내기·가져오기는 암호화된 파일을 기본으로 하며, 사용자가 직접 실행한다.
- 첫 4명은 APK의 동일 버전을 쓰되 각자 별도 앱 설정으로 시작한다.

### 4.4 파일 가져오기 카드 안전 규칙

- 첫 실행 시 앱 알림과 삼성 메시지 알림 접근 안내·요청을 완료한 뒤 정책·카드·거래내역 온보딩을 시작한다.
- 카드 끝 4자리는 사용자가 직접 입력하며 기본 화면에서는 `••••`로 마스킹한다.
- 신한카드 엑셀의 카드 식별값 중 설정 카드의 앞 3자리와 일치하는 거래만 장부 후보로 삼고, 다른 카드 거래는 가져오지 않는다. 은행 PDF는 카드 식별값이 없어 가져오기 대상에서 제외한다.
- 같은 앞 3자리의 서로 다른 실물 카드가 파일의 고유 카드 식별자로 구분되면 가져오기를 중단하고 `카드 하나만 선택해 결제 내역을 다시 받아 주세요.`를 표시한다.
- 식별값이 마스킹되어 실제 카드 중복을 판별할 수 없는 경우에는 경고 안내를 표시하되, 설정 카드 앞 3자리와 일치하는 행은 가져온다.
- 가져온 거래에는 설정 카드 끝 4자리를 내부적으로 연결해 승인·취소 매칭의 정확도를 높인다.
