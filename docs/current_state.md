## 작업 원칙 (2026-10-21~23 사용자 합의)

- 각 작업은 `dev`에서 브랜치를 만들고 PR로 병합한다. 안정 브랜치 이름은 `main`이다.
- **`app/` 코드가 바뀐 병합은 병합된 `dev`를 Android 에뮬레이터(Pixel_8)에서 실행해 확인한 뒤 다음 작업으로 넘어간다.** 충돌이 없어도 한다. 문서·이미지만 바뀐 병합은 `app/` 변경이 없음만 확인한다(2026-10-24 사용자 합의).
- 휴대폰에는 실제 사용 앱(`io.github.cjsan30.shinhanhae.calculator`)이 있다. 휴대폰 확인은 검증 앱(`.verify`)에만 설치한다(아래 "검증 앱 빌드" 참고).
- 한 곳에서만 쓰는 작은 함수는 따로 파일을 만들지 않고 쓰는 파일에 둔다. 계산·판정 로직은 `domain/`에 두고 같은 이름의 테스트를 둔다.
- 보고할 때 바뀐 파일·버전을 구체적으로 적는다.
- 릴리스(서명) 빌드와 Play 업로드는 사용자가 직접 한다. 서명 비밀번호는 묻거나 저장하지 않는다.

- 원인: 계좌번호를 "숫자 10자리 이상이 이어진 첫 글자 조각"으로 찾았다. 실제 PDF는 머리글 계좌번호를 은행이 가려 보내 이 조건에 맞지 않았고, 표 안 이체 행 `내용`의 긴 숫자가 대신 잡혔다. 실제 PDF는 숫자를 가린 구조만 출력해 확인했고, 실제 값은 코드·테스트에 넣지 않았다.
- 수정(`fix/bank-pdf-account-last4`): `계좌번호` 이름표 옆 값을 먼저 읽고, 없으면 표보다 위쪽 머리글에서만 계좌 모양 숫자를 찾는다(날짜로 시작하는 발급번호·조회일시 제외). 지어낸 숫자로 테스트 3개를 추가했다.
- 거래내역 가져오기 화면의 카드·은행 이름은 그대로 둔다(사용자 결정).

| 내부 PDF 측정 비교가 공정하지 않음 | 측정 화면의 "N% 빨랐습니다"는 과거 방식 1회와 현재 방식 3회 중앙값을 비교한다. 현재 방식은 각 측정의 첫 회차가 가장 느리다. 실측 원자료는 [15-pdf-benchmark.md](15-pdf-benchmark.md) | 두 방식 모두 같은 횟수로 재고 첫 회차 제외 검토 |
| 내부 PDF 측정 결과 줄바꿈 | 측정 결과 두 줄(`small`)이 붙어 "1회 측 / 정현재"처럼 이어져 보인다 | 결과를 줄 단위로 표시 |
| 은행 PDF 긴 `내용`의 가맹점 누락 | 실제 입출금내역 PDF에서 `내용`이 길면 글자가 x≈346(입금 칸 범위)에서 시작하거나 두 줄로 나뉘어, 30행 중 11행이 가맹점 대신 `적요`(예: 체크카드)로 들어왔다(2026-10-31 마스킹 구조 확인) | 열 범위·여러 줄 처리 수정 검토 |
| 대시보드 맞춤 함수 lint 경고 | `DashboardScreen.tsx`가 판단 함수(`budgetHeadingFits`, `fitScale`)를 함께 내보내 `only-export-components` 경고 2건 | 작은 함수는 쓰는 파일에 둔다는 원칙에 따라 유지 중 |

## 환경 메모

- 새 체크아웃에서는 Gradle 전에 `npm run android:sync`가 필요하다. 셸 기본 Java가 8이라 `JAVA_HOME=C:\Program Files\Android\Android Studio\jbr`, `ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk`를 지정한다. sync 후 생기는 gradle 파일 줄바꿈 변경은 커밋하지 않는다.
- **새 PC(2026-10-31)**: 기본 Node는 20.20.2(scoop nvm)다. 다른 프로젝트(`init_`)가 Node 20을 고정해 기본값은 바꾸지 않았다. Node 20에서는 `npm run test:run`이 jsdom 로드 중 `webidl.util.markAsUncloneable is not a function`으로 시작하지 못한다. 이 저장소는 CI와 같은 Node 24(24.22.2, nvm으로 설치)를 셸 PATH 앞에 두고 실행한다: `$env:Path = "$env:USERPROFILE\scoop\persist\nvm\nodejs\v24.22.2;$env:Path"`. pre-push 훅도 같은 셸에서 푸시해야 통과한다.
- pre-push 훅은 로컬 설정이다(`git config core.hooksPath .githooks`). 새로 clone하면 다시 켠다.
- **이력 재작성(2026-10-22)**: 계좌번호 제거로 모든 커밋 해시가 바뀌었다. 이전에 clone한 체크아웃이나 worktree(예: `.claude/worktrees/exciting-varahamihira-851ef5`의 `fix/onboarding-test-flake`)에는 옛 이력이 남아 있으므로 푸시하지 말고 새로 clone한다.
- **Kotlin 정규식은 기기에서 확인한다**: Android 정규식 엔진(ICU)은 데스크톱 JVM과 다르다(예: `(?U)` 플래그 미지원). 단위 테스트는 데스크톱 JVM에서 돌아 이런 차이를 잡지 못하고, 최상위 정규식 오류는 `SmsBridgePlugin.kt` 전체 초기화를 실패시킨다(작업 7에서 실제로 발생 후 수정).
- **검증 앱 빌드**: 임시 Gradle init script로 debug 변형에 `applicationIdSuffix '.verify'`와 앱 이름 "신청해 계산기 검증" 리소스를 덧씌워 `assembleDebug` 후 `adb install -r --user 0`. 설치 전 패키지명과 Android Debug 서명이 기존 검증 앱과 같은지 확인한다. 평소 debug 빌드는 실제 앱과 같은 패키지 ID이므로 휴대폰에 그대로 설치하지 않는다.
- 에뮬레이터 `Pixel_8`에는 이전 감사의 합성 데이터가 든 앱이 있다(사용자 지정 정책 기간 1~31일, 700,000원 계획, 큰 글자·고대비 설정, 시스템 글꼴 200%). 2026-11 기간 계획이 하나 확정돼 있다(#31 확인). 확인 후 추가한 테스트 파일·증빙은 지운다.
- GitHub가 CI 상태나 PR head를 늦게 반영하는 일이 있었다. 모든 단계가 성공했는데 job이 진행 중으로 남으면 `gh run rerun`으로 다시 돌린다.
